## Evidence Rules

Use three evidence labels throughout:

- Direct: the source explicitly names or clearly states the issue.
- Implied: the source gives enough contextual evidence to code the issue even if the exact term is absent.
- Absent: the source does not support the code.

Do not erase implied DPPRA signals simply because the source does not use formal policy language. Do not invent mechanisms, budgets, identities, or demographic facts that are not supported.

When using inference, write it plainly: "Implied because..." or "Weakly implied because..."

**Rule E3 - Conservative coding default.** Do not code a construct as `0 = absent` merely because the exact formal term is absent. If the source gives enough contextual evidence to infer the construct, code presence as `1 = present`, evidence label as `1 = weakly implied` or `2 = implied`, and explain the inference in the memo.

This rule applies especially to:

- Ethical Beneficence: a broad claim that AI will benefit humanity, education, development, care, dignity, democracy, access, or flourishing qualifies as Ethical Beneficence even if it is made by one participant, is contested, or is not the dominant thread position.
- Integrity: code weak/implied Integrity when a commenter uses AI misuse as a disqualifying argument, highlights institutional hypocrisy, or questions epistemic reliability.
- DPPRA resource alignment: if commenters describe any existing mechanism, benefit, institutional process, public pushback, open-source mechanism, or collective-action pathway that connects discourse to practice/resources, do not code alignment as `0`.
- Learner posture: education-adjacent governance or school surveillance threads may receive a learner posture code when the source discusses students, learning environments, AI pedagogical methodology, or student cognitive/developmental outcomes.
- Detection vs surveillance: generic account creation, login, sign-up, or rate limiting is access control, not detection-verification. Code detection-verification as present only when the source describes a targeted check applied to a specific user, document, behavior, or event.
- Objective-function ethics: if even one participant questions what AI optimizes for, what counts as success, or how system goals shape culture, behavior, education, labor, or governance, code objective-function ethics as at least weak.

### Beneficence Split

Beneficence must be split.

Mechanical Beneficence means usefulness, efficiency, productivity, automation, workload reduction, cost reduction, performance improvement, ease of use, tool access, or functional benefit.

Ethical Beneficence means human flourishing, educational development, empowerment, democratic access, student well-being, care, reduction of inequality, dignity, autonomy, or ethically meaningful improvement.

A source can be high in Mechanical Beneficence and low in Ethical Beneficence, or the reverse. Do not collapse them.

### Justice vs Equity Rule

Code Justice as present when the discussion centers on allocation of scarce opportunities, institutional benefits, burdens, rights, public goods, jobs, admissions, grades, scholarships, research funding, credentials, labor impacts, democratic control, or structural distribution, even if the word "justice" is not used.

Code Equity only when the source discusses differential access, unequal advantage, stratified effects, group-based distribution, disability, class, race, geography, gender, language, institutional exclusion, or other unequal social positioning explicitly or strongly by implication.

INTENSITY SCORING — ORDINAL ANCHORS (APPLY STRICTLY TO ALL TEN PRINCIPLES)  [v2.5 — back-ported from ICST v2.5 §4.1]

  0 — Absent: not mentioned, not operationalized, and not reasonably inferable.
  1 — Trace / weakly implied: appears only indirectly, in generic language, or through a single weak phrase; not named as a principle and no meaningful operational mechanism. Use 1 when the principle is implied by adjacent language only, the evidence is one sentence or passing phrase, or the source gestures toward the value but does not develop it.
  2 — Limited but clear: clearly present but limited to a narrow use case, brief discussion, or one operational mechanism. Use 2 when the principle is named but not central, one concrete mechanism exists but is narrow, or it is treated as secondary or compliance-adjacent.
  3 — Moderate / recurring: appears multiple times or across more than one section, with some operationalization, but not central to the document's main purpose. Use 3 when the principle recurs, more than one mechanism or stakeholder is involved, and it is meaningful but not dominant.
  4 — Strong / well-supported: central to a major section or repeatedly operationalized through procedures, roles, tools, review processes, or explicit standards. Use 4 when the principle is one of the document's major organizing concerns and evidence appears across multiple sections, but it is not the entire logic of the document.
  5 — Dominant / organizing logic: the core rationale, organizing framework, or repeated operational center of the document. Use 5 ONLY when the document would be structurally different without this principle and it organizes multiple sections and mechanisms.

  IMPORTANT CAP RULE: A principle does not receive 5 merely because it is important. It receives 5 only if it is structurally dominant.

  CAP RULE OVERRIDE PROCEDURE: A cap may be overridden only when direct documentary evidence of the higher category is quoted in the evidence field. The coder must state: "CAP OVERRIDE — [rule] — evidence: [quote]."

**DPPRA alignment coding guidance:**

- Code alignment based on the current observable investment and practice direction, not only the aspiration stated in the source.
- If the source diagnoses a decoupling problem and proposes public-good alternatives, code the current trajectory's alignment and note the proposed alternative in the memo.
- Code `0 = no visible alignment` only when there is no evidence of any investment, mechanism, policy, or material practice that supports even a symbolic connection between stated ethical goals and actual practice.
- Code `1 = symbolic` when there is a stated commitment, named policy, institutional affiliation, public-good claim, or ethical framing that connects discourse to the resource context, even if the connection is thin, performative, or contested.
- Code `2 = procedural` when there is evidence of an actual process, expenditure, institutional mechanism, public pushback, governance mechanism, or implementation pathway, even if it does not produce redistributive outcomes.
- Code `3 = operational` when investment or practice is demonstrably directed toward the stated ethical goal, even if imperfectly.
- Code `4 = material/substantive alignment` when investment demonstrably reduces inequality or increases public benefit in practice.
- In threads where the source argues that current AI investment is decoupled from public benefit, but also acknowledges real AI benefits or mechanisms, code at least `1 = symbolic` rather than `0`.
- Decoupling Signal: whether there is a gap between what is said, what institutions formalize, and what appears materially supported
- Market Capture Signal: low, moderate, high, or unclear
- Dominant Value Type: Mechanical, Institutional, Market, Pedagogical, Redistributive, Humanistic, or mixed

Forum-specific focus: look for anger or concern about cost, debt, access, subscriptions, wasted spending, institutional priorities, labor shifting, surveillance, data capture, platform dependency, and who actually benefits.

Score on where the anchor's LITERAL criterion is met — distribution across the
document — not on how important the topic feels. Apply the discriminators
mechanically.

  0  ABSENT      — the dimension is not raised in the text at all.
  1  INCIDENTAL  — appears once, in passing; no elaboration, example, or stake.
  2  MENTIONED   — named/described in >=1 passage but UNDEVELOPED; no mechanism,
                   consequence, or example attached.
  3  DEVELOPED (LOCALIZED) — substantively treated WITH a concrete example,
                   mechanism, or stake, BUT confined to one section or a few
                   adjacent passages; the argument does not keep returning to it.
  4  CENTRAL (DISTRIBUTED) — recurs across MOST major sections and the argument
                   repeatedly returns to it, tied to a mechanism/consequence/
                   recommendation. Removing it would leave several passages
                   unintelligible, BUT the document could be rebuilt around a
                   different spine.
  5  DEFINING (SPINE) — pervasive AND load-bearing: the single organizing logic
                   of the text. Remove it and there is no document, only
                   disconnected fragments; it survives no reframing.
  8  applicable but unclear   ·   9  definitionally not applicable

  THE THREE DISCRIMINATORS (apply in order, mechanically):
   • 2 vs 3 — Is a concrete mechanism / example / stake attached? NO -> 2.
              YES -> at least 3.
   • 3 vs 4 — COUNT the major sections the dimension appears in. One section,
              or a few adjacent passages -> 3. Most major sections, the argument
              keeps returning -> 4.
   • 4 vs 5 — Removal test + PROPORTION GATE (both required for a 5; see below).

  ►► THE 5 IS OPERATIONALIZED (from v2.11 — apply BOTH tests, not a gut call):
     A dimension may be coded 5 ONLY IF:
       (i)  PROPORTION GATE — it is the dominant subject of the BODY by section
            share: it is the leading theme in a PLURALITY of the document's major
            sections (count them), AND no other dimension occupies more. Read the
            BODY distribution, NOT the title, abstract, or a single loud passage.
       (ii) REMOVAL TEST — remove it and the document collapses into disconnected
            fragments; it survives no reframing.

     section share, neither is 5 unless co-equal (see CAP).

  TWO-SIDED ANCHORS — calibrate BOTH ends to the same bar:
   • HIGH (earn the 5): a paper whose entire thesis is that privacy law is broken;
     every major section is about privacy; remove it and nothing remains -> 5.
   • TRAP (looks like 5, is not — TITLE-ANCHORING): a statute titled
     "...Transparency... Act" mentions transparency in the title and intro, but its
     BODY is mostly enforcement duties, impact assessments, and remedies. Section
     share for transparency is one of several, not the plurality -> transparency
     is 4 (distributed), NOT 5. Score the body, never the headline word.

    LOCATE vs INTERPRET — the dividing line: everyone should converge on WHICH passage
    is the evidence (pre-interpretive). How strongly that evidence reads for a STANDPOINT
    field (I3) may legitimately differ — that residual is data, not error. Locating the
    evidence removes the noise so the real divergence shows.
    NARRATIVE REQUIREMENT (right-sized): for your spine 5(s) and for any cost/benefit
    indicator you fire, name the locating passage (cap_rule_notes / evidence_excerpts).
    Repeated values are ALLOWED — a true all-4 document is fine — but each value must be
    earned field-specifically, never asserted from the topic.

I1. COST/BENEFIT TRIGGER TEST (the binary fix — extends PART E).
    For EACH cb_cost_* / cb_benefit_* indicator (0/1), before coding 1, ask:
      1. is THIS exact cost/benefit named or clearly implied — or only generally
         related to "AI risk/benefit"?
      2. who experiences it?
      3. which source sentence supports it?
      4. a real asserted effect, or just a possible background concern?
    Code 1 ONLY if the source NAMES or CLEARLY IMPLIES that specific cost/benefit.
    Code 0 if the document is merely ABOUT AI risk/benefit in general. A passing,
    diffuse, or topic-level mention is NOT presence. (Distinct from PART H's "diffuse
    collective = 6", which is WHO bears a cost ONCE asserted — not whether to fire it.)

I2. BENEFICENCE — MECHANISM vs ETHICAL (a real conceptual split; score independently).
    • eth_beneficence_mech = the OPERATIONAL good the system DOES — efficiency,
      capability, accuracy, labor-saving, access delivered by a described mechanism.
    • eth_beneficence_eth = the appeal to human dignity / wellbeing / flourishing / care
      as a VALUE (the normative good intended).
    A document may assert BOTH; score each from its OWN evidence (I0). Do NOT let "this
    is about benefit" collapse them to one number.
      WORKED: an EdTech doc pitting "computational efficiency" (mech) against
      "preservation of human pedagogical agency / authentic learning" (eth) fires both,
      independently. A thread urging that AI be "treated with care, not as a disposable
      tool" is eth (dignity-as-value), with mech low (no operational benefit mechanism).

I3. STANDPOINT FIELDS — DO NOT FORCE CONVERGENCE (RUN_04 lens-swap finding).
    Two clusters move with the reader's THEORETICAL standpoint, not with coder error.
    Code them honestly from the text; their cross-coder divergence is SIGNAL — do NOT
    reach for a "safe" middle to match the other coders or the document's self-framing.
      • the ACTOR CROSSWALK (cb_primary_cost_bearer / _material_beneficiary /
        _value_capturer): WHO bears cost / captures value reads differently from
        different standpoints (a critical reading sees the public bearing cost and the
        vendor capturing value where a face-value reading sees the institution). Apply
        PART H's legend to the text in front of you; do not normalize.
      • decoupling_signal: the say-do gap is salient to an institutional reading, muted
        to a face-value one. Code what THIS text supports (PART B).
    NAMED-NOT-DESCRIBED FLOOR (validity guard for decoupling + int_*/alignment): when a
    document NAMES a mechanism/framework/procedure but its DESCRIPTION lives off-page
    ("see our framework", "evaluations took place", link-deferred), the int_* /
    dppra_alignment intensity is CAPPED LOW (<=2 — named, not described), and
    decoupling_signal is FLOORED UP, not suppressed: professed-principle density with the
    verifiable detail moved off-page IS a say-do signal. (A corporate self-report that
    link-defers every mechanism must not read as high-alignment.)

I4. ASSESSOR vs ASSESSED — score what the DOCUMENT does, not what it analyzes.
    For analysis / audit / index / scholarly genres, code the document's OWN mechanism
    and alignment, NOT the mechanisms of the actors it studies. An AI-safety INDEX that

------------------------------------------------------------------------------
  [J1] DPPRA STRENGTHS -- rhetoric-to-reality ladder
------------------------------------------------------------------------------
WHAT DPPRA MEASURES: how far a document actually travels from talk to action on
responsible AI. Five components, shallow → deep:
  D  = Discourse       — framing/argument that responsible AI matters (the talk itself)
  P1 = Policy          — stated principles, commitments, rules, standards
  P2 = Practice        — actions actually performed
  R  = Resources       — resources the AUTHORING BODY ITSELF has committed/deployed
  A  = Accountability  — mechanisms by which someone actually answers for outcomes

══ THE CORE RULE (governs P1, P2, R, A — apply this BEFORE the ladder) ══
Score the EVIDENCE GRADE, not how important the topic feels or how often it is mentioned.
The decisive line is VERIFIABLE ACTION TAKEN vs STATED GOAL:

  • STATED GOAL / INTENT / VALUE  → CEILING 2.
      Markers: "we are committed to", "we aim / strive / seek to", "we will", "we believe",
      "our principles hold that", "is designed to", "intended to", "we prioritize".
      Aspiration is rhetoric. It CANNOT exceed 2, no matter how elaborate.

  • VERIFIABLE ACTION TAKEN → FLOOR 3.
      A specific, named thing DONE that a third party could check — concrete and
      past/perfective: "we conducted", "we published", "we established in 2024",
      "we allocated $X", "an external auditor reviewed", "required and enforced under §Y".
      If you cannot name the action, it is NOT a 3.

  THE TEST, per component: "Did they DO it, or SAY they would?"  Done → 3+.  Said → ≤2.

══ THE 0–5 LADDER ══
  0 ABSENT      — component not present.
  1 INCIDENTAL  — one passing mention, no elaboration.
  2 STATED ONLY — appears as goal/intent/value/commitment with NO verifiable action
                  attached. (This is where decoupling lives.)
  3 ENACTED (LOCALIZED)   — ≥1 named, verifiable action taken, but a single instance / one section.
  4 ENACTED (DISTRIBUTED) — multiple named verifiable actions, recurring across major sections,
                  tied to mechanisms/consequences. Operationally load-bearing.
  5 DEFINING    — the component's enacted actions are the organizing spine (proportion gate +
                  removal test). At most ONE component may be 5.

══ WHAT COUNTS AS A VERIFIABLE ACTION, PER COMPONENT (the 2→3 gate) ══
  P1 Policy:        an ADOPTED, named policy/standard/rule in force WITH specifics.
                    3 = "our Acceptable Use Policy prohibits X" · 2 = "we value safety" / bare principle list.
  P2 Practice:      a named practice ACTUALLY PERFORMED.
                    3 = "we ran a frontier-safety evaluation on model X" · 2 = "we test rigorously".
  R  Resources:     ►► FIRST-PARTY TEST (v0.2 — apply FIRST):
                    A resource the document MANDATES / REQUIRES / RECOMMENDS that OTHERS provide
                    ("agencies shall fund", "developers must allocate", "providers shall dedicate staff")
                    is NOT R — it is Policy. The author is telling someone else to spend.
                    R counts ONLY a NAMED resource the AUTHOR ITSELF funds / staffs / builds / operates:
                    3 = "we built watsonx.governance / our 30-person red team / we allocated $Xm" · 2 = "we invest in safety".
                    Statutes, recommendations, journal articles usually commit NO first-party resource → R = 0–2.
  A  Accountability:a named mechanism that OPERATES to make someone answer (external audit, oversight body
                    with authority, enforceable sanction, remedy/redress process).
                    3 = "an independent board must approve releases / penalties under §Y" · 2 = "we hold ourselves accountable".
  D  Discourse:     scored on DEVELOPMENT, not action (D is the talk dimension by definition).
                    2 = framing named but thin · 3 = developed argument w/ concrete example/stake in one area
                    · 4 = the responsible-AI framing recurs across most sections · 5 = the document IS that argument.

══ dppra_alignment_score_code (0–5): the rhetoric-to-reality MATCH for the whole document ══
  Does the verifiable action (P2/R/A) live up to the discourse/policy (D/P1)?
  0 = pure rhetoric, no verifiable action behind any claim (fully decoupled).
  2 = procedural: some named procedures, but the big claims remain stated-only.
  3 = operational: the central claims are backed by named, verifiable actions.
  5 = every major claim is matched by checkable action + outcome evidence.
  Named-not-described floor: if mechanisms are link-deferred / off-page / unnamed, alignment ≤ 2.

══ TIE-BREAKER ══
  Torn between two rungs → code the LOWER, unless the higher rung's FULL criterion (for 3+, a NAMED
  verifiable action; for R, a NAMED first-party committed resource) is explicitly met. Aspiration NEVER
  clears the 2→3 gate.

------------------------------------------------------------------------------
  [J2] int_*_intensity + cb_*_intensity/strength -- evidence-grade gates
------------------------------------------------------------------------------
PART 1 — int_*_intensity (the OPERATING-MECHANISM gate) ════════════════════
Each int_* field measures how intensely a SPECIFIC integrity MECHANISM is OPERATING in the text —
NOT whether the topic is nearby. The decisive rule mirrors rhetoric-to-reality:

  • A NAMED mechanism actually OPERATING ("we ran red-team X", "a data-provenance log is maintained",
    "an external benchmark was applied") → 3+.
  • The integrity CONCERN merely named / discussed with NO operating mechanism → ceiling 2.
  • The integrity DOMAIN does not apply to this document → 0  (or 9 if definitionally N/A).

  ►► DO NOT read an integrity mechanism into a document because the topic is ADJACENT.
     int_research / int_assessment / int_academic require the SPECIFIC mechanism, not generic relevance:
       - int_academic_intensity  = academic-honesty mechanism (plagiarism/cheating/authorship controls).
                                    Most non-education docs = 0.
       - int_research_intensity   = research-integrity mechanism (data-fabrication / reproducibility /
                                    research-misconduct controls). "AI used in research" is NOT this. Most = 0.
       - int_assessment_intensity = assessment-VALIDITY mechanism (is an assessment instrument still valid).
                                    Most non-assessment docs = 0.
       - int_system_tevv_intensity= Testing/Evaluation/Validation/Verification of the AI SYSTEM.
                                    3+ = a named TEVV process performed; 2 = "we test" stated.
       - int_data_prov_intensity  = data provenance/governance mechanism actually operating.
                                    3+ = a named data-governance practice; 2 = "data quality matters" stated.
       - int_epistemic_intensity  = epistemic-integrity mechanism (truthfulness / misinformation / model
                                    honesty controls). 3+ = a named mechanism; 2 = concern raised only.

  LADDER (int_*): 0 absent / domain N/A · 1 passing mention · 2 concern named, NO operating mechanism ·

  >> v2.14 CLARIFICATION A (bare-mention floor): a passing MENTION of an integrity concern that the
     document does NOT substantively develop as its own subject = 0 or 1 (the domain is not engaged),
     NOT 2. Reserve 2 for a concern the document substantively RAISES as its issue while operating no
     mechanism. (Stops int_academic/research/assessment drifting to 2 on docs that merely touch the topic.)
  >> v2.14 CLARIFICATION B (int_ is NOT first-party, unlike R): score the substantive engagement of the
     mechanism in the document's SCOPE, regardless of WHO operates it. A document that mandates or
     specifies a detailed mechanism (e.g., a memo requiring agencies to run TEVV) engages it at 3+ even
     though OTHERS execute it. The first-party / enactment signal is already carried by DPPRA's R / P2 / A
     -- do NOT double-count it in int_.
                  3 ONE named operating mechanism (localized) · 4 multiple, distributed · 5 spine.

════════════════════ PART 2 — cb_*_intensity/strength (the MAGNITUDE-EVIDENCE gate) ════════════════════
cb_cost_presence_strength / cb_benefit_presence_strength = how strongly costs / benefits are present overall.
cb_cost_intensity / cb_benefit_intensity = the magnitude of the dominant cost / benefit.
Rate the EVIDENCED magnitude, NOT the rhetorical weight or how alarming it sounds.

  • 2 = a cost/benefit is ASSERTED or named but NOT evidenced — no specified harm/benefit, affected party,
        mechanism, or magnitude. ("AI poses serious risks", "AI brings huge benefits" → 2.)
  • 3 = a named cost/benefit WITH a concrete affected party OR example OR mechanism of harm/benefit.
  • 4 = WITH magnitude / scope / distribution evidence, recurring across the document.
  • 5 = the cost/benefit analysis is the organizing spine.
  • 0 = none present · 1 = one passing reference.

  Codex tends to read rhetorical alarm as magnitude — hold the line: unspecified "serious risk" is 2, not 4.
